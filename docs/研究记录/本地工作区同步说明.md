# 本地工作区同步说明

## 配置目标

- Windows 本地工作区：`D:\vibelab\iypt`
- GitHub 仓库：`https://github.com/sifangmian-lab/ipyt-chalktrick`
- 日常研究分支：`develop`
- 稳定分支：`trunk`

本次仅在 `develop` 更新同步配置，没有合并分支，也没有改动既有研究模型、实验数据或结论。

## 同步方式

仓库中的 `code/tools/sync_workspace.ps1` 默认本地路径为 `D:\vibelab\iypt`，默认分支为 `develop`。脚本可放在任意目录运行，行为如下：

1. 目标目录不存在或为空时，克隆 `develop` 到该目录。
2. 目标目录已有文件但尚不是 Git 工作区时，先为现有文件建立本地 Git 快照，再通过 `--allow-unrelated-histories` 并入 `origin/develop`。
3. 目标目录已经是本项目工作区时，获取远端更新并执行快进同步。
4. 同名文件内容冲突或分支分歧导致无法自动合并时，不擅自选边；若合并已经开始，则中止合并并回到本地快照。
5. 不自动推送本地文件，不保存 GitHub 令牌。

## 已有文件目录的并入规则

用户已确认 `D:\vibelab\iypt` 中有现有文件，要求并入项目。安全流程为：

1. 检查 Git 用户名和邮箱，并确认远端分支可访问。
2. 在原目录初始化 Git，登记 `origin` 并获取 `develop`，此时尚不覆盖文件。
3. 使用 `git add --all` 和本地提交保存现有文件，输出合并前快照的提交号。
4. 将 `origin/develop` 合并到当前目录。无冲突时，本地原有文件与仓库文件都保留。
5. 有冲突时不自动判断哪个版本正确，不强制覆盖；脚本尝试 `git merge --abort` 回到快照。

快照遵循现有 `.gitignore`：被忽略路径不会进入 Git 快照，脚本会给出警告。重要文件若被忽略，应先解除忽略或另行备份。脚本不会自动把本地快照或合并结果推送到 GitHub。

## 使用

目录不存在或为空时，可以直接克隆：

```powershell
git clone --branch develop https://github.com/sifangmian-lab/ipyt-chalktrick.git D:\vibelab\iypt
```

已有文件的目录，或以后需要更新时，运行同步脚本：

```powershell
powershell -ExecutionPolicy Bypass -File <脚本所在路径> -LocalPath 'D:\vibelab\iypt' -Branch 'develop'
```

若脚本已经位于工作区内，命令为：

```powershell
powershell -ExecutionPolicy Bypass -File D:\vibelab\iypt\code\tools\sync_workspace.ps1
```

本地修改或并入结果需要同步回 GitHub 时，应先检查、提交，再推送：

```powershell
git -C D:\vibelab\iypt status
git -C D:\vibelab\iypt add .
git -C D:\vibelab\iypt commit -m "更新本地研究工作区"
git -C D:\vibelab\iypt push origin develop
```

## 权限边界与完成状态

当前 agent 运行在独立的 Linux 沙箱中，不能直接访问或控制用户 Windows 电脑的 `D:` 盘。因此，本次能够完成的是远端脚本、流程测试和配置记录；**本地目录是否已并入及是否同步成功，只能以该脚本在用户电脑上的实际运行结果为准**。

认证交给 Git 凭据管理器处理。不要把令牌写进脚本、远程 URL、文档或提交信息。

## 验证记录

2026-10-25 使用临时 Git 仓库验证了两种情形：

- 本地与远端文件不重名：合并后双方文件均保留，工作区状态干净。
- 同名文件内容冲突：自动合并失败后中止合并，本地文件内容及快照提交均恢复。

当前环境没有 Windows PowerShell，因此上述验证针对脚本采用的 Git 流程；Windows 本机执行结果仍需实际运行确认。
