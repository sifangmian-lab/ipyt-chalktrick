# 工作区完整性标签修复方案（带回滚）

> 日期：2026-10-25
> 现象：DSH 受限（workspace-write）模式下，`pwsh` 无法写入 `D:\vibelab\iypt\ipyt-chalktrick` 下任何文件/子目录（连新建文件都拒绝），但能读、能执行只读命令；`D:\vibelab\iypt` 根目录内可写。
> 结论：**不是 DACL 权限问题，而是 Windows 强制完整性标签（Mandatory Integrity Label）不匹配。**

## 1. 原因

Windows 的沙箱进程运行在 **Low 完整性级别**（`whoami /groups` 显示 `Mandatory Label\Low Mandatory Level`）。强制完整性控制有一条默认规则：**低完整性进程不能写入比它更高完整性的对象位置（no-write-up）**，DACL 里即使有 Modify/FullControl 也不起作用。

当前状态：

| 对象 | 完整性标签 | Low 沙箱可写？ |
|---|---|---|
| `D:\vibelab\iypt`（工作区根） | **Low**，显式 `(OI)(CI)` 继承 | ✅ |
| `D:\vibelab\iypt\ipyt-chalktrick`（仓库） | 无显式标签，默认 **Medium** | ❌ |
| 仓库内已有文件/子目录 | 同上，默认 Medium | ❌ |
| 新建的仓库内文件 | 若在 Medium 父目录下创建，仍 Medium | ❌ |

DSH 给工作区根目录设了 Low 标签和可继承标志，但仓库子目录是在该标签设置**之前**就存在的，不会自动回填标签；于是出现“根目录能写、仓库不能写”。之前修 ACL（WRITE_OWNER）解决的是另一个错误，不能绕过完整性限制。

## 2. 修复思路

把**仓库子树**的现有对象统一改标为 Low，并带 `(OI)(CI)` 继承标志；之后该目录下新建的文件也会继承 Low，受限沙箱即可正常写入。

- 只改 **强制完整性标签**（SACL 中的 Mandatory Label）；
- 不改文件内容、所有者（Owner）、DACL 访问权限；
- 不动工作区根目录及其它目录（参考 PDF、旧文档保持 Medium）；
- 全程可逆：把子树重新标为 Medium 即回到原状。

> 为什么选“子树”而不是“整个工作区”：仓库是日常写入目标；`论文/` 等参考资料保持 Medium 更稳。若要全工作区统一，可把 `-Scope` 改为 `D:\vibelab\iypt`，回滚同理。

## 3. 工具与命令

脚本：`code/tools/workspace_integrity.ps1`

| 模式 | 作用 | 命令 |
|---|---|---|
| `Status` | 只读：显示 token 完整性、Scope 根与样本文件标签、对象数 | `pwsh -NoProfile -File code/tools/workspace_integrity.ps1 -Mode Status` |
| `Pilot` | 在临时目录预演：建目录+文件 → 标 Low → 标回 Medium → 删除；验证两个方向都可用 | `... -Mode Pilot` |
| `Apply` | 自动先跑 Pilot；备份前置信息；递归标 Low；抽检失败自动回滚 | `... -Mode Apply` |
| `Rollback` | 把 Scope 子树递归标回 Medium，并抽检 | `... -Mode Rollback` |

默认参数：

```text
-Scope       D:\vibelab\iypt\ipyt-chalktrick
-RecoveryDir D:\vibelab\iypt\.integrity-recovery
```

`Apply` 会在 `RecoveryDir` 生成：

- `integrity-apply-<时间戳>.log`：前置状态、pilot 输出、icacls 输出、抽检结果；
- `ROLLBACK-<时间戳>.ps1`：一键回滚脚本（打印绝对路径）；
- 控制台打印 `ROLLBACK_COMMAND`。

## 4. 执行步骤（有人值守）

1. **前置检查**：`git status` 干净或已提交（当前 A2 提交 `bcdcaa5`）；关闭正在写这些文件的编辑器/杀毒扫描等。
2. **Pilot**：`-Mode Pilot`。必须看到 `PILOT=OK`。**2026-10-25 实测：当前非管理员账号会在这一步失败（Low→Medium 升不回去）**，此时必须停止，不执行 Apply（详见第 9 节）。
3. **Apply**：`-Mode Apply`。脚本会先跑 Pilot，Pilot 不通过会直接拒绝 Apply。若执行中任一步失败，脚本会**自动回滚**并返回非零；查看日志后停止，不重复执行。
4. **沙箱内验证**（关键）：在受限（workspace-write）模式下执行：
   - 在仓库内创建/写入/删除临时文件；
   - `python code/tools/check_regression.py`（只读运行，不写文件，确认环境仍正常）；
   - 需要真实写盘时再跑一次短仿真（如 S5b）确认能覆盖结果文件。
5. **记录**：把 pilot、apply、验证结果写入 `docs/研究记录/更新日志.md`。

## 5. 回滚

任选其一：

```powershell
# 推荐：脚本回滚（会抽检）
pwsh -NoProfile -File code/tools/workspace_integrity.ps1 -Mode Rollback

# 或直接运行 Apply 时生成的脚本（路径以控制台/日志为准）
pwsh -NoProfile -File 'D:\vibelab\iypt\.integrity-recovery\ROLLBACK-<时间戳>.ps1'
```

回滚后的状态：仓库子树显式标为 **Medium**；功能上等价于原来的“默认 Medium”，但会多出显式标签。抽检样本应显示 `Medium` 或 `DEFAULT(=Medium)`。

**非管理员权限下的回滚风险（已被 Pilot 实测证实）：** 把标签从 Low“提高”到 Medium 需要相应权限。当前非管理员账号执行 `icacls /setintegritylevel M` 会返回 0 但标签不变（见第 9 节），因此**在非管理员账号下没有可用回滚，禁止 Apply**。只有满足以下任一条件才可以考虑 Apply：
- 有管理员 PowerShell 可执行回滚脚本；或
- 已对仓库做完整外部备份（zip/另一块盘），并接受“恢复备份后文件为 Low 标签”的差异；或
- 只做临时实验、可整机还原。

## 6. 风险与缓解

| 风险 | 影响 | 缓解 |
|---|---|---|
| 降低仓库文件完整性级别 | 任何 Low 完整性进程（如沙箱浏览器）若同时具备 DACL 写权限，可修改这些文件 | 仓库本来就是用户自有工作区、DACL 未变；可随时回滚；敏感资料不在仓库内 |
| 回滚需要升标签权限 | 非管理员可能无法从 Low 提到 Medium | Pilot 预验证；失败则停止；必要时用管理员 PowerShell 回滚 |
| 文件被占用导致部分失败 | 少量文件标签未改 | 脚本用 `/C` 继续并统计失败数；抽样验证；可关闭相关程序后重跑 |
| `.git` 也被标 Low | 不影响正常 git；Medium 的 git/编辑器仍可读写 Low 对象 | 已包含在 Scope；回滚覆盖 `.git` |
| 显式标签残留 | 回滚后并非“无标签”，而是显式 Medium | 功能等价；如需完全去除，可再手动清理（非必要） |
| 提权执行 | 不必要且扩大影响面 | 方案**不要求管理员**；仅当回滚方向验证失败时才建议管理员执行回滚 |

## 7. 验收标准

- [ ] Pilot：`PILOT=OK`（Low 与 Medium 两个方向都可设置并读回）。**2026-10-25 实测当前非管理员账号不满足此项**，故本轮按设计不执行 Apply；
- [ ] Apply 仅在“回滚方向可用”（管理员 PowerShell 或外部完整备份）时执行；
- [ ] Apply：`APPLY=OK`，`icacls` 抽检（仓库根、代码、`.git/HEAD`、结果说明）均为 Low；
- [ ] 受限沙箱：可在 `ipyt-chalktrick` 内新建/覆盖/删除文件；
- [ ] `python code/tools/check_regression.py` 全部 PASS；
- [ ] `git status` 干净、`git log` 仍为 `bcdcaa5`；
- [ ] 回滚演练（可选）：执行 `-Mode Rollback` 后抽检为 Medium，再 Apply 一次恢复 Low。

## 8. 不采用的替代方案

- **修改 DACL / 加 Everyone 写权限**：绕不过 no-write-up，且扩大权限面；
- **以管理员运行沙箱或提权**：不解决完整性级别，且有安全代价；
- **把整个工作区标 Low 而不做回滚方案**：范围过大，参考资料被降低完整性；
- **改用完全权限模式**：可行；**本会话已切换为完全权限并验证可直接写仓库**，是当前采用的方式，但不是受限模式下的长期修复；
- **新建 Low 副本**：见第 10 节，可逆且不需要管理员，但会增加一份工作副本。

## 9. Pilot 实测结果（2026-10-25）

运行环境：完全权限（unconfined）下的 Windows PowerShell，token 为 **Medium**（`whoami /groups`）；`Scope` 默认仓库子树，样本标签均为 `DEFAULT(=Medium)`；工作区根为 Low 并带 `(OI)(CI)` 继承。

`-Mode Pilot` 输出：

```text
PILOT dir: Low -> L:Low (exit=0) -> M:Low (exit=0)
PILOT file: L:Low M:Low
ERROR: Pilot: rollback direction (Low -> Medium) failed; this account cannot raise labels. Do NOT run Apply; use an elevated PowerShell for rollback.
```

结论：

1. 临时目录在 Low 父目录下创建，初始标签就是 Low；把它标 Low 是 no-op；
2. **`icacls /setintegritylevel M` 在非管理员 token 下静默失败**：退出码 0，但标签仍为 Low；
3. 因此“Apply 后可用回滚脚本恢复”在本账号下**不成立**；脚本的 Pilot 门禁按设计拒绝 Apply；
4. **本方案在当前账号下不执行 Apply。** 当前会话已切换为完全权限（`danger-full-access`），仓库可直接写入（已验证：仓库内建/写/删临时文件成功，token=Medium，513 个对象），无需修改标签；
5. 如果将来必须回到 workspace-write 受限模式，优先使用“临时切完全权限”，其次考虑第 10 节的“新建 Low 副本”，最后才是“管理员协助的标签修改 + 管理员回滚”。

## 10. 备选：新建 Low 副本（无需升标签，可逆）

如果确实需要受限模式下可写、又不希望动现有 Medium 文件，可利用“新对象继承 Low”的机制：

```powershell
# 在 Low 标签的工作区根下新建目录（新目录会继承 Low）
$src = 'D:\vibelab\iypt\ipyt-chalktrick'
$dst = 'D:\vibelab\iypt\ipyt-chalktrick-sandbox'
Copy-Item -LiteralPath $src -Destination $dst -Recurse -Force
# 新目录及其文件应显示 Low；之后可在受限模式下写入副本
```

- **优点**：原仓库完全不动；回滚 = 删除副本目录（Low 对象，受限/完全权限均可删），无需升标签；
- **缺点**：多一份工作副本，需要在副本里完成研究后再用 git 合并/推送，路径与远程同步要额外管理；
- **验证**：`-Mode Status -Scope D:\vibelab\iypt\ipyt-chalktrick-sandbox` 应显示样本为 Low；再在受限模式测试写入；
- 本方案未在本轮执行；当前会话已是完全权限，不需要副本。
